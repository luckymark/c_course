# C语言学习笔记本

> **开始前请注意：在线输入限制**
> 当前在线环境中的 `scanf`、`getchar`、`fgets(..., stdin)` 无法交互读取键盘输入。在线实验请修改变量的初值，或使用 `sscanf` 从字符串读取；键盘输入练习请在本地 GCC / Clang 中运行完整 C 程序。

参考书目：电子科技大学出版社《C与C++程序设计》，戴波主编；陈文宇、丘志杰、卢光辉副主编。

本项目使用 Jupyter Notebook 提供可运行的 C 语言课堂实验，章节编排与教材对应：

1. C语言程序设计概述
2. 基本数据类型及运算
3. 控制语句
4. 数组与结构
5. 指针
6. 函数

学完六章后，可继续两个进阶实践：

- **进阶实践1_文件读写.ipynb**：读取成绩文本，检查错误，生成独立报告。
- **进阶实践2_多文件编程.ipynb**：学习 enum、typedef、头文件保护与独立编译，让同一统计模块服务于报告和验收程序。

进阶实践的短实验可在线运行；完整项目在本地编译。源码与样例数据位于仓库 content/practice（在线文件浏览器中的 practice 目录），各专题提供逐个文件的链接与运行步骤。文件报告用 `wx` 创建新报告，遇到已有输出文件会失败，请换一个新报告名。

每章包含学习目标、“预测—运行—修改—解释”实验、分层练习和完整的本地 C17 程序。新增应用题提供作答单元、边界验收样例与分级折叠提示；先完成作答，再展开参考答案。各章本地程序分别保存为 chapter01.c 至 chapter06.c。

第 2、3 章先显示一个输入的短作答区。完成后再展开默认折叠的批量验收代码，将答案复制到同名标记区域，分别检查7组和6组用例。验收工具中的数组与遍历代码由课程提供；输入表与期望表长度不一致时会明确报错。使用“运行全部”仍会执行折叠单元，尚未填写的答案显示 FAIL 属于正常作答反馈。

第 4 章包含选择排序的逐轮演示，以及数字字符统计、删除普通空格、选择排序三道可运行自测题。只填写 BEGIN ANSWER 与 END ANSWER 之间的代码，保留用例与验收逻辑；初始模板出现 FAIL 表示尚未完成，正确实现应分别达到 6/6、6/6、8/8 PASS。空串、容量边界、空数据、重复值和负数均有对应反馈。各自测器从用例表计算总数，添加用例后通过数与总数会随之更新。

第 6 章的综合练习要求独立完成成绩统计函数，提供可运行的逐例反馈。初始占位函数会显示 FAIL，这是待完成练习的预期状态；完成函数后应为 7/7 PASS。修改函数定义后重启内核并从头运行。综合练习的完整参考程序包含人数输入、动态分配、统计与释放，可在本地编译验证。

第 4 章按“基础必做—综合应用—选做挑战”标明学习路线，不要求一次完成所有题目。第 5 章主例集中于分配、赋值、统计与释放，二重指针、扩容和字符串解析归入选学。第 6 章另有“从空白文件完成程序”的第二阶段验收，用于检查独立组织程序的能力。

贯穿案例逐章发展为成绩统计程序：报告输出 → 成绩计算 → 合法性与及格判断 → 结构体数组统计 → 动态分配成绩空间 → 通过只读参数与返回值组织统计函数。每章都可独立重启内核运行，不依赖上一章的变量状态。

## 在线学习

打开 [课程网站](https://luckymark.github.io/c_course)，选择章节笔记本，使用 **C17** 内核，从上到下运行单元。首次启动需要下载 WebAssembly 内核，请等待内核就绪。

- `Shift+Enter` 运行当前单元。
- 修改 `{ ... }` 中的局部变量后，可以重复运行该单元。
- 修改函数、结构体或顶层变量定义后，使用 **Kernel → Restart Kernel and Run All Cells**，避免旧定义影响结果。
- 每次学习结束，按下面的步骤下载自己的作业；浏览器中的修改不会提交到此仓库。

Notebook 支持直接执行语句，这是交互环境的功能。普通 `.c` 文件仍需要头文件和 `main` 函数。第 1 章分别提供了完整程序和在线实验；不要把所有单元直接拼接为 `.c` 文件，也不要在 Notebook 中手动调用 `main()`。

## 保存作业与继续学习

1. **保存当前作答**：在打开的 Notebook 中选择 **File → Save Notebook**，然后选择 **File → Download**，将 `.ipynb` 文件下载到电脑。保存按钮不等于下载备份。
2. **确认备份**：在电脑的下载目录中找到文件，改名为便于辨认的名字，例如 `第2章_我的作业_2026-09-20.ipynb`，保留 `.ipynb` 扩展名。Notebook 文件用于继续作答，不是可直接编译的 `.c` 源文件。
3. **重新打开**：回到课程页面，点击左侧文件浏览器上方的 **Upload Files**（向上箭头），选择该文件。上传完成后双击文件名，确认自己修改的代码和笔记仍在；选择 C17 内核，从头运行以重新建立变量和函数状态。
4. **避免覆盖**：如果上传时提示同名文件已存在，先取消，在电脑上给待上传文件换一个名字，再上传。每次结束学习，重新下载并保留日期不同的备份。

**课程更新时**：先下载自己的作业，再获取教师提供的新版章节。也可到 [仓库的 content 目录](https://github.com/luckymark/c_course/tree/main/content) 打开所需 `.ipynb`，使用 **Download raw file** 下载；在电脑上改成含“新版”和日期的独立文件名后上传。将旧作业与新版分开打开，只迁移自己的答案和笔记，再运行新版验收。刷新网页不作为确认课程版本的方法，也不要通过清空浏览器数据来更新课程而丢失作业。

首次进行本地编程，请先完成 [第 1 章](https://github.com/luckymark/c_course/blob/main/content/第1章_C语言程序设计概述.ipynb)“C程序的编译与运行”中的环境检查，再继续后续章节的 `.c` 练习。

## 标准输入的限制

当前固定的浏览器版 xeus-cpp 0.10.0 中，C17 内核的行为如下：

| 操作 | 浏览器实测行为 |
| --- | --- |
| `printf` | 正常输出 |
| `sscanf` | 可以从字符串读取数据 |
| `scanf` | 返回 EOF，不弹出键盘输入框 |
| `getchar` | 返回 EOF |
| `fgets(..., stdin)` | 返回 NULL |

这些是浏览器内核的限制，不是 C 语言的规则。在线实验使用明确赋值或 `sscanf`；第 2 章保留了检查 `scanf` 返回值的完整本地程序。`std::cin` 属于 C++，不能用于本课程的 C17 内核。

键盘输入练习请将完整程序保存为 `.c` 文件，使用本地 GCC 或 Clang 编译，例如：

```bash
cc -std=c17 -Wall -Wextra -Wpedantic hello.c -o hello
./hello
```

本地原生 Jupyter 内核与浏览器内核是不同的运行环境，上表不用于判断原生内核的支持情况。

## 构建与验证

构建环境使用 Python 3.14（允许更新补丁版本），固定 JupyterLite 0.8.3、jupyterlite-xeus 5.1.0；WebAssembly 环境固定为 xeus-cpp 0.10.0，使用 emscripten-forge-4x 软件源。版本声明分别位于 `build-environment.yml` 和 `environment.yml`。这两份文件固定核心依赖，不是全部间接依赖的锁文件。

安装 [micromamba](https://mamba.readthedocs.io/en/latest/installation/micromamba-installation.html) 后，在仓库根目录执行：

```bash
micromamba create -n c-course-build -f build-environment.yml -y
cp README.md content/README.md
micromamba run -n c-course-build jupyter lite build --contents content --output-dir dist
micromamba run -n c-course-build python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

打开 <http://127.0.0.1:8765/lab/>。`environment.yml` 用于构建浏览器内核，不能直接作为本机原生 C 内核的安装环境。

[浏览器检查脚本](https://github.com/luckymark/c_course/blob/main/tests/browser_smoke.py) 的模块说明包含测试安装和运行命令。它在全新浏览器配置中检查 C17 内核版本、函数、单元重复执行、内核重启、输入限制，并逐章执行站点中的所有非空代码单元。测试只在自己的页面响应中启用应用调试入口，不修改发布站点。

关键实验的预期输出保存在对应单元的元数据中，由浏览器检查直接核对；留给学生的作答单元不作为已完成答案。[本地程序检查脚本](https://github.com/luckymark/c_course/blob/main/tests/native_examples.py) 从六章提取带验收元数据的完整 C 程序（包括折叠的应用题参考答案），以严格警告选项编译，并验证输出与退出码。综合练习覆盖正常输入、边界和错误输入；这些程序只在 Notebook 中维护。

[进阶项目检查脚本](https://github.com/luckymark/c_course/blob/main/tests/native_projects.py) 直接编译 content/practice 中的源码，在临时目录中验证真实文件的读取、报告内容与错误路径，并验证各源文件独立编译、链接和模块验收。进阶完整源码只在 .c/.h 文件中维护。运行 `python tests/native_examples.py` 和 `python tests/native_projects.py` 检查章节示例与进阶项目；环境需提供 C17 编译器。

[练习答案检查脚本](https://github.com/luckymark/c_course/blob/main/tests/exercise_solutions.py) 将折叠参考答案填入同一份学生作答模板，使用原有验收逻辑编译和运行，避免另写一套测试数据；同时将第 6 章的完整参考程序与实际学生验收单元组合验证。运行 `python tests/exercise_solutions.py` 执行这些检查，浏览器检查也会验证发布的答案及综合练习组合。

GitHub Actions 在构建及 Chromium 检查成功后才发布 GitHub Pages。
